## 4. 架构与技术栈：这一段最值得记

“这是一个纯前端静态应用。HTML 定义页面结构，CSS 用网格布局、媒体查询和主题变量适配界面，JavaScript ES 模块实现规则和交互。数独在 `main.js` 中维护局面，`hint.js` 做提示；扫雷分成 `minesweeper.js` 规则控制器和 `minesUI.js` 界面层。两个游戏共享 `audio.js`，利用 Web Audio 本地合成声音；进度通过 localStorage 保存。发布在 GitHub Pages，本地 Python 只提供开发预览，Node.js 只运行测试，都不是线上业务后端。”

```text
浏览器 ← HTTPS → GitHub Pages（提供静态文件）
  ├─ index.html：两游戏入口与切换
  ├─ main.js ↔ hint.js / core/even.js：数独状态、规则、提示
  ├─ minesUI.js ↔ minesweeper.js：扫雷界面、引擎、订阅通知
  ├─ audio.js：共用音频实例、设置、声音调度
  └─ localStorage：同一浏览器中的进度/纪录/偏好
```

有逻辑上的界面、控制与规则划分，但不把整个项目说成严格 MVC：数独 `main.js` 仍混合了算法、状态与 DOM，后续可以进一步拆分。没有使用 Vue、React、Spring Boot、MySQL，也没有自建 REST API、实时服务器或线上登录。

## 5. 代码定位与能解释的关键点

在编辑器用 Ctrl+F 搜函数名；文件链接可从仓库中打开。

| 文件与函数 | 老师可能问 | 你应该说明 |
|---|---|---|
| [main.js](../src/main.js)：`searchGrid`、`solve` | 数独如何求解？ | 深度优先回溯。优先选择候选数最少的空格（MRV），尝试候选；无候选返回无解；失败恢复为空。MRV 减少分支，不能保证所有局面恒定耗时 |
| 同文件：`hasUniqueSolution`、`digSymmetric`、`digRandom` | 怎样保证题只有一个解？ | 先生成完整答案，再试着挖空。对副本计数，发现第二个解就停止；只有恰好一个解时保留挖空，否则还原。不是只检查某一个答案是否合法 |
| 同文件：`analyzeDifficulty`、`generatePuzzle` | 难度由什么决定？ | 空格目标与单候选/隐性唯一位置分析共同决定，重试和兜底仍保留唯一解；不是专业人类技巧评级，也不是“空越多一定越难” |
| 同文件：`inputNumber`、`updateCellFeedback`、`checkWin` | 正确、冲突、完成如何判断？ | 输入写入 `state.userGrid`；错误反馈会与已知答案比较，也有同行列宫/对角线冲突反馈。完成时逐格对比答案。错误不只包含肉眼可见的重复数字 |
| [even.js](../src/core/even.js)：`makeEvenCells`、`evenAllows` | 偶数规则怎么保证可解？ | 从当前答案里取本来为空且答案为偶数的格作标记；检查标记格只允许 2/4/6/8。它增加约束，不会排除当前答案 |
| [hint.js](../src/hint.js)：`showCandidates`、`highlightUniqueLocation`、`fillOneCorrect` | 三级提示是 AI 在线算的吗？ | 是本地规则推理，没有在线模型调用。依当前棋盘求候选，寻找确定位置；受已有错误值影响，未必每次都有可填位置 |
| `main.js`：`undo`、`redo`、`saveProgress`、`loadProgress` | 历史与存档怎么做？ | 普通输入历史存行列和前后值，索引向前/向后移动；局面序列化成 JSON，保存到 localStorage。刷新恢复与云同步是不同能力 |
| [minesweeper.js](../src/minesweeper.js)：`placeMines`、`countAdjacent` | 首击安全怎么做？ | 第一次揭开时重新布雷，将点击格及合法八邻域排除；洗牌候选位置取固定数量的雷，然后统计每格邻域雷数 |
| 同文件：`revealFlood`、`chord`、`_checkWin` | 自动展开与胜利条件？ | 用显式栈展开零格连通区域并揭开边缘数字。周围旗数等于数字时可以快速展开，但误标旗仍会输。揭开所有非雷格才赢，旗数正确不代表必胜 |
| [minesUI.js](../src/minesUI.js)：`render`、`syncPause`；引擎 `subscribe` | UI 与逻辑怎样联系？ | UI 收操作调用引擎；引擎更新状态通知订阅者，再刷新界面。计时 tick 只更新 HUD，避免整盘每秒重建导致焦点丢失 |
| [audio.js](../src/audio.js)：`unlock`、`voice`、`startMusic`、`setPaused` | 为什么点击才播放？ | 浏览器自动播放策略要求用户手势；通过 resume 解锁 AudioContext，用振荡器和 Gain 包络合成声音，独立控制音效和音乐；`setScene` 在数独的舒缓音乐和扫雷的紧张脉冲之间切换 |
| [index.html](../index.html)：`switchGame`；`main.js`：`syncActiveView` | 两游戏会互相抢键盘或计时吗？ | 切换改变可见视图，调用扫雷生命周期并发事件；数独停止隐藏计时、限制键盘。音频模块 URL 统一，防止同一文件因不同查询参数被实例化两次 |

## 6. 常见追问：简短回答

**为什么选网页版？** 一个链接就能让普通用户试玩，满足最终发布要求，也减少一个月内的安装包、审核和多端维护工作。

**为什么不用框架和后端？** 当前是单人本地规则游戏，规模较小。原生 ES 模块足够；若未来增加账号、可信排行或跨设备同步，再引入服务端。GitHub Pages 提供文件托管，不替项目执行数据库操作。

**数据保存在哪？换电脑还有吗？** 在当前站点、当前浏览器配置的 localStorage。换设备、清理站点数据可能丢失；线上与 localhost 来源不同，不共用存档。不存账户密码。

**能防作弊吗？** 客户端里有答案和逻辑，用户能查看/修改。适用于单人休闲体验，不能当可信竞技排名；真正在线排行要服务端校验，不能只相信浏览器提交的分数。

**算法复杂度呢？** 数独回溯最坏情况是指数搜索，不能声称 O(81)；MRV 和解数达到 2 就停止是剪枝。扫雷邻域固定最多八格，统计和一轮连片展开相对棋盘格数 N 为 O(N)，显式栈最坏占 O(N) 空间。

**性能做了什么？** 页面无需框架构建，声音本地合成；数独 MRV 减少搜索，扫雷计时只刷新 HUD。没有正式压测就不报并发、秒开或“所有设备流畅”等结论。

**测试证明了什么？** `node --test` 当前有 34 项，包括实际数独生成器合法/唯一解、偶数约束、音频控制生命周期、扫雷首击安全、暂停、存档损坏及结束锁定。它不能证明所有浏览器与全部 UI 流程都无缺陷。

**用了 AI 吗？** 如实说明使用 AI 辅助实现、检查和整理文档；实际负责的工作以代码、提交和自己能解释的实现为依据。不把 AI 生成等同于经过充分测试，也不编造个人或队友贡献。

**你本人做了什么？** 先核对自己真正参与的内容再回答。例如可以打开 `07b8d6b` 解释双游戏生命周期修复、共享音频和手机插旗；队友的扫雷原始新增在 `983581b`。不要把队友新增的引擎全部说成本人独立完成。

**还有哪些不足、下一步怎么做？** 优先完善数独状态校验和完整 UI 走查，补完整 UI/胜负流程走查，再考虑按日期固定每日题与离线缓存；不临场承诺已经做完。

## 7. 当前边界：防止介绍与代码不一致

- “今日挑战”目前随机生成新局，并未按当天日期固定题目。
- 手动笔记已支持小号候选、取消、擦除和保存恢复；笔记只是玩家推测，不参与完成判定，也不会自动删除其他格子的候选。
- 数独提示填入、普通输入与撤销历史的整合尚不完整；普通操作历史已统一限制为最近 50 次，并同步保存游标。演示普通输入撤销，不宣称所有操作都已形成完整事务历史。
- 数独存档目前只做基础解析，校验与存储禁用降级尚不全面；扫雷有更具体的尺寸、雷数和类型校验。不要笼统说两种游戏都能处理任意坏存档。
- “离线”仅指已加载后的规则在本机执行；没有 Service Worker 冷启动离线缓存。本机 HTTP 备份使用磁盘文件，才是断网演示的可靠备用路径。
- 高级扫雷窄屏、完整胜负流程和扬声器实听，需要现场前本人走查；不要把自动测试冒充完整人工验收。
